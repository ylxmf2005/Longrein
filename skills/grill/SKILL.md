# grill

## 只把当前决定前沿交给用户

从当前对话和真实对象重建方向；有 `context.md` 时读取它和 Current Artifacts。把未决事项看成有依赖的决策树：前置决定尚未成立的分支先不问；当前可以决定的问题组成这一轮的决定前沿。

事实由 Agent 从代码、运行现场、文档和工具中查明。交给用户的是价值、偏好、范围、风险接受与授权。一个问题需要背景时，先讲清关系、推荐答案和代价；默认用户没有读过当前产物，也不把补查事实转交给他。

每轮提出当前前沿，依赖用户决定的分支等待回答，其余调查和已授权工作继续。答案会改变后续依赖，因此每轮之后重新计算，不沿旧问卷机械前进。

## 决定回到拥有它的地方

需要保存的决定写回拥有它的当前产物：任务承诺由 `shape` 修订 `context.md`，专业结论回到对应来源。没有所属产物时在对话中交付，不为质询另建 Task 或决定日志。已获授权按原动作与范围继续有效，不沉淀为未来任务的通用授权。

回答推翻任务方向或专业前提时，先修订受影响的权威来源，再继续展开依赖它的决定；不能让较新的聊天答案和较旧的持久产物同时有效。

## 在共同理解处停止

当承重分支已经决定或明确保持未决、没有关键假设被藏起来，需要保存的决定已经回到权威来源，质询结束。用户的困惑或“我不知道”不是同意；它必须保留为具名未知及其影响。

方向需要重开时用 `shape` 补齐；方向成立后继续当前请求已授权的工作。Grill 只负责质询，不替 `dev` 实现、`review` 独立证伪或 `test` 提供完成证据。
